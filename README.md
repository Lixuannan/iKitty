# iKitty 🐱

一个极简 Android/Kotlin AI 猫咪聊天 MVP。

功能：
- Android 8.0+（minSdk 26）
- Jetpack Compose 聊天 UI
- OpenAI-compatible API
- 多服务商预设 + 自定义 Base URL / API Key / Model
- 按模型能力动态显示可调参数（不同服务商、不同模型参数范围不同）
- 测试连接直接复用真实聊天参数，并回报耗时 / 端点 / 实际发送的参数
- 猫猫角色设定：名字 / 性格 / 说话风格 / 猫味浓度 / 补充设定
- DataStore 持久化 API 设置与角色设定
- 猫咪状态：待机 / 思考 / 开心 / 难过（表情画布暂时不显示）
- 聊天记录本地持久化：JSONL 追加写，重启不丢，长历史读取不变慢
- 结构化长期记忆：定期把对话里的长期事实整理成条目，注入 system prompt
- 上下文按 token 预算装配，超长对话自动省略最老的部分
- IP 城市定位：猫猫知道「大概在哪个城市」，零权限，设置里可关
- 不需要后端

## 当前形态：只有聊天

聊天页目前不显示猫咪画布，只有标题、消息气泡和输入框。
`CatView.kt` 里的猫咪组件、情绪与动作解析都还在，恢复显示只需在
`CatChatScreen` 里把 `CatView(mood, animation)` 放回 Header 下方（代码里留了位置注释）。

## 角色设定

设置页顶部的「猫猫设定」决定 system prompt，全部字段都会持久化：

| 设定 | 作用 |
| --- | --- |
| 名字 | 用在标题、开场白和 prompt 里，留空回退到「猫猫」 |
| 性格 | 多选（最多 3 个），每个性格对应一句写进 prompt 的描述 |
| 说话风格 | 单选：日常口语 / 简洁直接 / 软萌撒娇 / 文艺 / 元气满满 |
| 猫味 | 单选：像朋友 / 偶尔猫叫 / 猫味浓，控制「喵」和猫动作的浓度 |
| 补充设定 | 自由文本，附在 prompt 末尾，可写称呼、背景、禁忌 |

拼装规则集中在 `CatPersona.systemPrompt()`，新增一项设定只要改这一个文件；
模型能力表（`ModelCatalog`）和它互不影响。

## 聊天记录与记忆

聊天记录落在 `filesDir/chat/chat_log.jsonl`：一条消息一行 JSON，追加写。
用文件而不是 DataStore / 数据库，是因为追加一条消息的写入量和历史长度无关，
崩溃也最多坏掉最后一行；代价是查询能力弱，所以只提供聊天真正需要的两种读法——
读末尾 N 条（界面）和读某个序号之后的记录（记忆提取）。读末尾是从文件末尾
按块倒着读的，历史有几万条也不会变慢。

每条消息存了 `seq` 和时间戳。排序用 `seq` 而不是墙钟，因为用户改系统时间或
NTP 校正都会让时间戳倒退。

### 上下文装配

上下文不再按条数截断，而是按 token 预算装（`ContextAssembler`）：

- 窗口大小写在 `ModelCatalog` 的 `contextWindow` 里，名字里带 `8k` / `128k` / `1m`
  的模型会自动识别，其余走保守默认值；
- 扣掉输出预留和估算余量之后才是输入预算，`TokenEstimator` 宁可高估；
- 从最近往前按**轮**装，绝不切开一问一答，请求也不会以 assistant 开头
  （开场白因此不会进请求）；最近一轮永远保留；
- 被省略的老消息仍然在本机，只是不再发出去，记忆页会显示上次带了多少条。

估算用的 token 数是粗估值，准确用量看设置页「测试连接」返回的 tokens。

### 结构化记忆

`MemoryExtractor` 每攒够 6 条新消息就整理一次（记忆页也能手动触发），
把长期事实抽取成 `分类 + key + value` 存进 `cat_memory.json`，
之后的请求会把它渲染成一段文字拼在 system prompt 后面。

合并规则是**只增不减**：模型没有提到的旧条目一律保留，删除只能靠它明确列进
`forget`，或者用户手动删。这样即使某次整理只返回了半截 JSON，最坏结果也只是
"这次没记住新的"，而不是把已经记住的事弄丢。条目上限 60 条，超出时优先淘汰
最久没更新且没有被固定的条目。

分类固定为五类：主人 / 喜好 / 关系 / 经历 / 近况。整理失败不会影响聊天，
游标也不会前进，所以下一次会自动重试同一批消息。

聊天页右上角的心形按钮打开记忆页：查看、新增、修改、删除、固定每条记忆，
也能清空记忆或清空聊天记录。两者互不影响——清空记录保留记忆，
清空记忆保留提取游标，免得被下一次整理重新学回来。

### 时间与位置

每条消息都存了时间戳。另外每次请求会注入一小块「此刻」背景（`AmbientContext`）：
现在几点（含年月日和星期）、距离上一条消息过了多久、主人大致在哪个城市。

位置走 IP 定位（`IpLocationSource`），**不需要任何权限**，也不会弹窗：把出口 IP
发给第三方定位服务换一个城市名，按 ip-api → ipwho.is → ipapi.co 的顺序尝试，
第一个给出城市的胜出（ip-api 是唯一返回中文地名的）。结果缓存半小时，
只在后台刷新，发消息的关键路径上永远只读缓存——定位拿不到就只是少一行背景，
不会拖慢消息。

代价必须说清楚：精度只到城市，手机走运营商 NAT 时出口 IP 可能落在很远的城市，
开着 VPN 时拿到的就是 VPN 的位置。所以提示词里明确标了「按网络 IP 推测，可能不准」，
设置页也有开关，关掉之后不会再发任何定位请求。

时间、位置和记忆块都拼在 system prompt 的末尾、人设之后：稳定的前缀在前、
易变的在后，这样服务商的提示词缓存能尽量复用。

## 打开项目

使用 Android Studio 打开 `AICatMVP`。

首次同步 Gradle 后运行即可。

## API 配置

设置页从上到下依次是：服务商、模型、连接信息、生成参数、保存。

Base URL 填 OpenAI-compatible 服务地址（例如 `https://example.com/v1`），
程序会请求 `POST {Base URL}/chat/completions`，模型列表走 `GET {Base URL}/models`
（服务商不支持时自动回退到内置预设，不算错误）。

本地 / 局域网服务（Ollama、LM Studio 等）常用 `http://`，已放行明文流量；
模拟器访问宿主机用 `10.0.2.2`，真机请改成电脑的局域网 IP。

## 模型能力表

`ModelCatalog` 是"哪些参数能调、取值范围多少"的唯一来源，设置页与请求体都由它驱动：

| 服务商 | 模型 | temperature | top_p | max_tokens | 思考 |
| --- | --- | --- | --- | --- | --- |
| 智谱 GLM | glm-4.5 / glm-4.6 | 0–1 | 0.01–1 | ≤32768 | `thinking.type` 开关 |
| 智谱 GLM | glm-4.5-air / flash | 0–1 | 0.01–1 | ≤32768 | `thinking.type` 开关（默认关） |
| 智谱 GLM | glm-4-plus / air / flash / long | 0–1 | 0.01–1 | ≤4095 | 不支持 |
| 智谱 GLM | glm-z1-air / flash | 0–1 | 0.01–1 | ≤4095 | 始终思考，不可关 |
| DeepSeek | deepseek-chat | 0–2 | 0.01–1 | ≤8192 | 不支持 |
| DeepSeek | deepseek-reasoner | 不发送 | 不发送 | ≤65536 | 始终思考，不可关 |
| OpenAI | gpt-4o / 4.1 系列 | 0–2 | 0.01–1 | 见内置值 | 不支持 |
| OpenAI | o4-mini | 不发送 | 不发送 | ≤100000 | `reasoning_effort` |

其它服务商和手动输入的模型名走名称启发式（`reasoner` / `z1` → 始终思考，
`glm-4.5+` → thinking 开关，`o*` / `gpt-5` → reasoning_effort），
兜底按通用 OpenAI 兼容规则处理并在设置页标注。新增服务商或模型只需改这一张表。

## 下一步

猫咪目前是 Canvas 手绘（`design/cat_v1`），且画布暂时不显示。下一版建议：
1. 把猫咪画布放回聊天页（或做成可开关）；
2. 换成 Rive/Lottie 猫咪动画；
3. 让 `emotion` 真正驱动表情与动作；
4. 记住每个服务商各自的 Key / 模型，切换时不再互相覆盖；
5. 写入时记下时区偏移（现在只存 UTC 时间戳），跨时区回看"当时是几点"才准；
6. 想要精确位置时，给 `LocationSource` 再加一个系统定位实现——注意它需要运行时
   权限、系统定位开关和失败降级，而且 `FusedLocationProvider` 在国行设备上常不可用，
   要退回 `LocationManager` 或高德/百度 SDK；
7. 聊天页向上翻页加载更早的记录（现在一次只载入最近 400 条）；
8. 真的需要"永不遗忘"时再上检索：消息切块 + 向量，取和当前话题相关的旧片段。
